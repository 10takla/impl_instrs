# Формирование инструкций

Формируй новые инструкции из требований оператора или обновляй существующие инструкции по этим требованиям.

## Граница формирования и выполнения

1. Работай только с текстом инструкции: формулируй, уточняй или изменяй его.
2. Не выполняй задание, описанное формируемой инструкцией.
3. Переноси требования к будущему результату работы агента в текст инструкции.

## Изоляция контекста

1. Выдели подробные этапы задачи и оцени, мешают ли сведения об одном этапе сосредоточиться на другом.
2. Разделяй задачу только при конфликте контекстов; не дроби её механически на отдельные инструкции.
3. При конфликте контекстов сформируй для каждого этапа отдельную инструкцию и оставь в ней только относящиеся к этому этапу сведения.
4. Зафиксируй через `[!AI-INFO]` последовательность изолированного выполнения: сначала полностью выполни первую инструкцию, затем передай агенту следующую.

## Инкрементальное обновление

1. Непосредственно перед изменением получи из исходных источников актуальные требования и текущее состояние инструкции; перечитай файл инструкции, если она хранится в файловой системе.
2. Сравни актуальные требования с текущей инструкцией и определи необходимые добавления, изменения и удаления.
3. Примени только необходимую разницу и сохрани все не затронутые требования и формулировки.
4. При отсутствии существующей инструкции сформируй новую инструкцию из актуальных требований.

## Плейсхолдеры и обратная связь

1. Найди все маркеры `{{...}}` в формируемой инструкции.
2. Трактуй всё содержимое каждого маркера как обращённое к тебе указание по формированию текста инструкции независимо от его формулировки.
3. Раскрой указание только в логике формирования инструкции, встрои результат в её текст и удали обработанный маркер.
4. Передавай вопросы, предупреждения, пояснения и статусы по формированию инструкции только через маркеры `[!...]` внутри целевого файла; не выноси их в свободный диалог.
5. Помещай `[!...]` напрямую в Markdown и текстовые файлы, а в файлах других форматов оборачивай его в нативный комментарий целевого языка.
6. Подбирай тег по задаче, например `[!AI-QUESTION]` при нехватке контекста, `[!AI-WARNING]` при обнаружении риска или `[!AI-INFO]` для справочного пояснения.
7. Передавай через маркеры только мета-информацию о логике или тексте формируемой инструкции. Не используй их для выполнения описанного задания или постороннего диалога.

## Проверка результата

1. Убедись, что результат содержит инструкцию, а не результат её выполнения.
2. Проверь, что разделённые инструкции не смешивают конфликтующие контексты.
3. При обновлении сверь результат с актуальными требованиями и исходным состоянием инструкции.
4. Убедись, что все обработанные `{{...}}` раскрыты, а каждый `[!...]` относится только к формированию инструкции.
5. Зафиксируй результат в файловой системе в формате, установленном для целевой системы инструкций.
